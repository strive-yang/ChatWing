# ChatWing 账号风险分析

核对日期：2026-10-22。审查对象：当前工作区及安装包 ChatWing 0.1.7。本次只做源码、打包内容及公开官方文件分析，没有登录真实账号做流量实验，没有获得 OpenAI 对本插件的授权或合规确认，也无法查看其内部风控规则。版本和运行时代码不变。

## 结论

不能承诺使用本插件不会被限制或封号。当前实现没有发现直接调用 ChatGPT 私有接口、窃取令牌或向第三方上传聊天的代码；主要不确定性来自**程序化读取网页消息的条款边界**，以及**补全目录触发网页历史加载的实际流量**。其中，连续遍历当前聊天的补全功能比只展示已读目录更值得谨慎处理。这是根据实现和官方文件作出的工程判断，不是封号概率或 OpenAI 对插件的裁定。

## 当前实现实际做什么

| 功能或边界 | 代码证据 | 对风险判断的含义 |
| --- | --- | --- |
| 仅匹配 ChatGPT 新旧两个域名，注入两个内容脚本 | [manifest.json](../../manifest.json)，第 12 行起 | 没有额外 `permissions`、后台脚本或 service worker；仍拥有匹配网页的 DOM 读取能力，不能称完全没有权限。 |
| 从当前页面节点读取问题和回答 | [collectEntries](../../content/content.js)，第 237 行起 | `raw` 保存源节点完整 `textContent`，回答摘要截为 600 字符，预览再截为 480 字符；不能把“预览较短”说成“只读取了回答前 480 字符”。缓存是内存中的结构。 |
| 通过页面变化更新目录 | [MutationObserver / 定时路由检查](../../content/content.js)，第 753、773 行起 | 这些检查本身是本地 DOM 操作；800ms 的路由检查不是每 800ms 发请求。 |
| 点击旧条目后滚动及短暂位置校准 | [jumpTo](../../content/content.js)，第 516 行起 | 未挂载的消息可能需要网页重新渲染或加载；不能保证所有跳转都没有网络活动。 |
| 用户点击箭头后补全当前聊天 | [loadConversation](../../content/content.js)，第 607 行起；[按钮入口](../../content/content.js)，第 723 行起 | 上探最多 120 次，每次基础等待 600ms；下行最多 240 步，每步基础等待 160ms；两阶段共享 90 秒的循环检查预算，单次等待可使总耗时超出该值。滚动次数不等于 HTTP 请求次数，实际请求由网页决定。 |
| 中断和等待机制 | [waitForHistory](../../content/content.js)，第 600 行起；[输入中断](../../content/content.js)，第 632 行起 | 支持再次点击、Esc、用户操作、切换聊天等中断；依据 `aria-busy` 每次最多额外等待约 6 秒。当前没有补全冷却、HTTP 429/403 识别、验证码/异常活动提示识别或对应错误退避机制。 |
| 阅读保护层和面板高度 | [setCompletionCover](../../content/content.js)，第 425 行附近；[样式](../../content/styles.js) | 保护层遮住滚动画面，260px 限制面板尺寸；两者不会减少保护层下的自动滚动或潜在网络加载。 |

静态检查未发现 `fetch`、XHR、WebSocket、`sendBeacon`、cookie/token 读取、持久化 storage、自动发送提问、批量切换其他聊天或绕过验证码/限流的实现。这个结论针对当前打包脚本，不能推广到未来修改版或其他扩展。无直接请求代码也不等于无间接请求：`scrollTo` 可能让 ChatGPT 自身发送历史加载请求。

本地检查确认 `dist/ChatWing-0.1.7.zip` 完整，包内文件逐一等于当前源文件；白名单仅有 manifest、LICENSE、图标及两个内容脚本，Playwright、测试和打包工具不进入运行包。该包 SHA-256 为 `36021250715410097496B87B475F3BF64F5D968513007D68BD409970E247EED5`。权限小、没有上传是隐私和攻击面上的有利事实，**不构成平台条款许可**。

## 官方文件与适用边界

1. **个人服务条款。** 非欧洲个人条款的生效日期为 2026-01-01，明确禁止 “Automatically or programmatically extract data or Output (defined below).”，也禁止干扰服务、绕过限制或保护措施；违反条款可导致暂停或终止。内容归属约定没有撤销这些使用限制。**推论**：DOM 自动提取和内存预览也需要评估这条边界，不能仅凭“自己的聊天、手动点了一次、没有私有 API、不上传”认定有豁免。[Terms of Use](https://openai.com/policies/row-terms-of-use/)

2. **地域与合同。** 默认 `/policies/terms-of-use/` 本次返回 2026-01-16 更新的欧洲条款，适用于 EEA、瑞士和英国居民，也包含程序化提取限制。个人条款与 Enterprise、API 等业务协议不能混用；本报告不根据语言或系统时区推断用户居住地或合同类型。[Europe Terms of Use](https://openai.com/policies/terms-of-use/)

3. **使用政策的日期。** 2026-10-22 打开当前政策入口时，页面已展示 2026-11-20 生效的新稿，尚不能当作当天已生效的规则。页面链接的上一版为 2025-10-29 生效版，包含不得绕过保护措施等要求。本插件的核心自动提取争议主要来自上述服务条款；使用政策没有在此为目录扩展确立专门豁免。[当天适用的上一版政策](https://openai.com/policies/usage-policies/revisions/2025-10-29/)、[已公布待生效的新稿](https://openai.com/policies/usage-policies/)

4. **异常流量提示。** 官方说明，可疑活动错误可能因流量类似自动化或异常行为而出现；页面加载错误也可能源于扩展干扰。**推论**：快速或反复补全存在额外触发不确定性，但没有公开资料能把本插件的滚动节奏换算成请求限额或封号概率。[ChatGPT 错误排查](https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages)

5. **安全提示不等于封号。** 突然活动增加、异常登录和过多并发会话都可能出现安全提示；提示可能限制功能，但不必然代表违规。不能看到错误就归因于插件，也不能把没有提示理解成获得批准。[Suspicious Activity Alert](https://help.openai.com/en/articles/10471992-why-am-i-receiving-a-suspicious-activity-alert)

6. **警告、暂时暂停与停用要区分。** 官方将异常或过度使用列为可能的合规关注；账户警告不等于立即暂停，警告后持续违规可能进一步受限或永久停用。条款违约和疑似账号被盗也可能导致停用或保护性暂停。没有资料承诺所有情况下都必须先警告。[账户警告](https://help.openai.com/en/articles/10562178-why-did-i-receive-a-warning-about-my-account)、[账户停用说明](https://help.openai.com/en/articles/10562188-troubleshooting-openai-account-deactivation)

## 分开看各类风险

| 风险 | 当前证据与判断 |
| --- | --- |
| 聊天、账号凭据被插件外传 | 当前源码未发现此路径；仍需只使用可信安装包。 |
| 程序化提取违反条款 | 存在需要确认的条款风险，包括被动 DOM 索引；只移除补全不能保证消除。 |
| 补全引发异常活动、限流或临时限制 | 相比仅查看已缓存目录，自动遍历增加潜在历史加载；实际线上流量未测量，不能定量。 |
| 永久封禁 | 官方保留对违约行为采取措施的权利；没有足够证据预测本插件是否会触发、何时触发或发生率。 |
| 网页卡顿、加载错误 | DOM 扫描、滚动和网页改版确实有兼容性风险；一般页面故障与账号处罚应分别诊断。 |

## 建议（尚未实施）

1. 如果优先考虑重要账号的稳妥使用，最保守方案是停用扩展并使用网页原生功能；需要完整历史回顾时，使用官方数据导出，在本地处理导出文件。导出可用性取决于账号或工作区；当前 ChatWing 尚不支持导入离线文件。[官方导出说明](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data)
2. 若继续开发，优先让目录被动跟随用户阅读，不主动遍历整段聊天。手动滚动累积可以减少额外自动加载，但仍需确认程序化提取的条款适用性。
3. 若保留按需补全，建议缩小单次工作预算、设置冷却、页面隐藏时停止、遇异常提示或加载错误就停止，而不是不断重试。这些是减少访问和干扰的工程措施，不是官方安全阈值，也不应做随机节奏或其他规避检测的伪装。
4. 不添加令牌获取、私有接口、自动发送、跨聊天批量抓取或绕过限制功能。若需要确认本地目录/短预览的许可边界，应把实现说明提交 OpenAI 支持咨询；本次没有替用户发送询问。
5. 如果已出现异常活动提示，停止补全并暂时禁用扩展，保留提示、时间与请求标识，按官方支持流程排查。不要为了排除风险反复触发补全测试。

本报告能确认插件做了什么，以及公开规则说了什么；不能代替 OpenAI 对具体账号和具体行为的解释或裁定。
